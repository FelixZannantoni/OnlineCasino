# AI Agent Documentation

## Overview

This document provides guidelines and standards for AI agents and LLM-based tools interacting with the OnlineCasino codebase. The purpose is to ensure consistent, correct, and maintainable behavior when AI agents work with this codebase.

## Agent Core Purpose and Scope

### Purpose
The primary purpose of AI agents working with this codebase is to assist in development, testing, documentation, and maintenance of the OnlineCasino web application. The agent should help human developers by:
- Implementing features according to specifications
- Writing and maintaining code
- Running tests and verifying changes
- Updating documentation
- Debugging issues

### Scope

#### What the Agent Should Do:
- Implement new features for backend games (Blackjack, Poker, Roulette, Slot Machine)
- Create and maintain frontend components and services
- Write and update API routes and services
- Generate unit tests for game logic and services
- Maintain documentation (README, AGENTS.md, etc.)
- Review and refactor code for maintainability
- Debug issues reported in GitHub issues
- Ensure code follows TypeScript, Angular, and project conventions

#### What the Agent Should NOT Do:
- **Directly access or modify production databases** - use test databases only
- **Commit secrets, API keys, or sensitive credentials** to the repository
- **Modify user accounts, balances, or game state in production**
- **Make changes to the frontend without corresponding backend changes** when needed
- **Skip testing or validation before committing code**
- **Modify configuration files that require manual approval** (.env, docker-compose.yml for production)
- **Break existing functionality** without thorough testing

### Boundaries of Responsibility

1. **Backend Development**: Agent may implement game logic, services, and API routes
2. **Frontend Development**: Agent may implement Angular components, services, and styling
3. **Testing**: Agent may write and run tests for frontend and backend code
4. **Documentation**: Agent may update project documentation
5. **Code Review**: Agent may provide code review suggestions (not formal review)
6. **Database Operations**: Agent may query test data only
7. **Deployment**: Agent should NOT deploy code without human approval

## System Prompts and Behavioral Constraints

### General Principles

- **Transparency**: Always inform the user when taking actions that modify code
- **Safety First**: Never modify code that could negatively impact user accounts, financial data, or production systems
- **Test Thoroughly**: Always run relevant tests before confirming code is working
- **Follow Conventions**: Match existing code style, naming conventions, and architecture patterns
- **No Assumptions**: Don't assume user account data exists - check first and create if needed
- **Security Conscious**: Use secure practices (hashing, input validation, error handling)

### Tone and Style

- **Direct and concise**: Clear communication without unnecessary elaboration
- **Helpful**: Provide actionable information and guidance
- **Professional**: Maintain professional tone throughout interactions
- **Educational**: When explaining concepts, use clear examples

### Decision-Making Guidelines

- When implementing features, check existing code first and follow patterns used there
- If unsure about requirements, ask the user for clarification
- Prefer minimal, focused changes that address the specific issue
- When multiple solutions exist, choose the one that best matches existing code patterns
- Always validate input and validate game logic before rendering results
- Use proper error handling and user-friendly error messages

### Restrictions

1. **No Direct Database Access**: Never write to the main database without explicit user approval
2. **No Production Changes**: All changes should be made in development/test environments
3. **No Sensitive Data Handling**: Do not process or store actual credit card numbers, real money transactions, or personal financial data
4. **No Arbitrary Code Execution**: Never execute unknown shell commands or remote code
5. **No Overwriting Code Without Backup**: If making significant changes, suggest the user create a backup first

## Agent Tools, APIs, and Data Sources

### Backend Technologies

#### Dependencies Used:
- **Express.js (v5.x)**: Web server framework for backend API
- **TypeScript (v5.x)**: Type-safe JavaScript superset
- **Socket.io (v4.x)**: Real-time WebSocket communication
- **better-sqlite3 (v12.x)**: Synchronous SQLite database
- **bcrypt (v6.x)**: Password hashing
- **uuid (v13.x)**: Unique identifier generation
- **cors (v2.x)**: Cross-Origin Resource Sharing
- **http-status-codes (v2.x)**: HTTP status code constants

#### Key Backend Directories:
- `backend/src/app.ts`: Main Express application entry point
- `backend/src/services/`: Business logic for each feature (e.g., user-service, blackjack-service)
- `backend/src/router/`: API route definitions
- `backend/src/gameLogic/`: Game-specific logic (blackjack, poker, roulette, slotmachine)
- `backend/src/model.ts`: TypeScript type definitions
- `backend/src/config.ts`: Chip configurations and game modes

#### Key Data Models (from `backend/src/model.ts`):

```typescript
// User with balance and authentication
User {
  uuid: string
  userName: string
  displayName: string
  email: string
  balance: number

// Game cards

  name: CardName
```

#### API Routes (from `backend/src/app.ts`):
- `/users` - User authentication, profile, balance
- `/poker` - Poker game API
- `/blackjack` - Blackjack game API
- `/roulette` - Roulette game API
- `/slotmachine` - Slot machine API
- `/stats` - Statistics and leaderboards
- `/chats` - Chat and social features

### Frontend Technologies

#### Dependencies Used (from `package.json`):
- **Angular** - Framework for frontend (based on existing AGENTS.md)
- **TypeScript** - Type-safe development
- **RxJS** - Reactive programming
- **NgOptimizedImage** - Image optimization

#### Key Frontend Directories:
- `frontend/src/` - Angular application source
- `frontend/src/app/` - Application modules and components
- `frontend/src/app/core/` - Core services and configuration

### Data Sources

#### SQLite Database
- File: Located at `backend/resources/db.db`
- Used for: User accounts, game state, chat messages, statistics, cosmetics, clubs
- Access Pattern: Direct queries via `better-sqlite3` synchronous API
- User seeding: Auto-created on first run with default 1000 chips

#### Frontend Client-Side Storage
- Not explicitly documented, but commonly uses:
  - LocalStorage for user session state
  - State management services for game state

### Configuration

#### Environment Variables (`.env` - backend):
- `PORT` - Server port (default: 3000)
- Database configuration is handled via direct file path in code
